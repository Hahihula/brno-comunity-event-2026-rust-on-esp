Než začneme, krátké shrnutí. Dva sliby: zaprvé, Espressif bere Rust vážně, není to jen hobby projekt. Zadruhé, na konci budete znát přesně tři příkazy, které vás dovedou od ničeho k běžícímu firmwaru. Nic víc. Pokud si máte zapamatovat jediný snímek, zapamatujte si ten poslední.
Aktuální stav

Rust je plnohodnotnou volbou

Není to komunitní experiment ani obálka kolem C. Espressif oficiálně podporuje Rust jako plnohodnotný vývojový jazyk vedle ESP-IDF.

  • Vlastní HAL, vlastní ovladače, vlastní nástroje — vytvořené a udržované pro čipy ESP
  • Stabilní API, ne předverze v1
  • Dokumentované, verzované a vydávané spolu s čipy
Upřímné upozornění

Je mírně pozadu za C SDK.

ESP-IDF je referenční SDK. Nové čipy a funkce periferií dostává jako první a nabízí nejširší pokrytí příklady.

Řekněme si toto upozornění nahlas — ESP-IDF je referenční SDK a k novému čipu nebo úplně nové periferii se vždy dostane jako první. Rust je trochu za touto hranicí.

Rust

Pro naprostou většinu projektů je Rust jednoduše lepší nástroj — a už dnes je skutečně připravený pro produkční použití.

Rozdíl se měří v měsících, ne v letech — a s každým vydáním čipu se zmenšuje.

Praktické pravidlo: pokud potřebujete funkci z datasheetu vydaného v tomto čtvrtletí, použijte ESP-IDF. Pro všechno ostatní Rust není kompromis — je to lepší výchozí volba.
Proč si jej vybrat

Co skutečně získáte

Bezpečnost

Žádné chyby s pamětí

Vlastnictví (ownership) a borrow checking eliminují přetečení bufferů a use-after-free chyby, které dominují embedded CVE.

Nástroje

Cargo odvede práci

Závislosti, buildy, testy, dokumentace, linting i cross-kompilace — jeden nástroj, žádné ručně psané Makefiles.

Škálování

Async, který sedí

Embassy přináší async do mikrokontroléru, takže Wi-Fi a senzory si přestanou překážet.

Simulace

Wokwi vestavěný

Funguje bez problémů se simulátorem Wokwi — z CLI i z VS Code.

Navíc: systém typů zachytí celou řadu logických chyb už při kompilaci a ekosystém crate balíčků je sdílený se zbytkem světa Rustu — není třeba ho pro každého vendora vynalézat znovu.

Tři výhody, každá jedním dechem. Pro C vývojáře: už nemusíte řešit argument bezpečnosti paměti. Pro Rust vývojáře: Cargo a skutečný ekosystém crate plný knihoven připravených pro no_std, pro spoustu senzorů a dalších komponent. A async je to, co skutečně mění způsob psaní firmwaru — Wi-Fi a práce se senzory přestanou být callbacky. Bonus: vše funguje hladce se simulátorem Wokwi, z CLI i z VS Code — pro vyzkoušení nepotřebujete desku.

Začínáme

Tři kroky: toolchain, flasher, generátor projektu.

Jsme v polovině. Všechno dosud byl kontext, všechno odteď si můžete dnes večer napsat do terminálu. Tři části — toolchain, flasher a generátor.
Krok 1 · Toolchain

Tu těžkou část už máte

Předpokládejme, že máte nainstalovaný rustup. Pokud ne, rustup.rs je jediný příkaz — ale odtud už Rust prostě funguje.

RISC-V čipy

Standardní Rust — hotovo

Řady C, H a P používají standardní RISC-V. Cílí na ně běžný stabilní Rust toolchain. Není třeba nic dalšího instalovat.

Xtensa čipy

Potřebujete espup

Xtensa nemá upstream LLVM backend, proto vám espup toolchain sestaví a nainstaluje.

ESP32ESP32-S2ESP32-S3 
$ cargo install espup --locked
$ espup install
$ # poté v každém novém shellu: . $HOME/export-esp.sh
Toto je zdaleka nejčastější otázka, proto přesná odpověď. RISC-V je standardní, takže jej stabilní Rust zvládne bez čehokoli navíc. Xtensa není v upstreamu, proto espup instaluje toolchain vytvořený přímo pro něj. espup udělá vše — stačí jej spustit.
Krok 2 · Flashování

Jak dostat kód do čipu

Možnost A

cargo-espflash

Čistý Rust, funguje vedle cargo build a kromě flasheru poskytuje také monitor.

Možnost B

esptool.py

Nástroj dodávaný s ESP-IDF. Pokud už máte IDF nainstalované, je k dispozici a funguje bez problémů.

$ cargo install cargo-espflash --locked

# board-info, monitor, erase, read-flash, save-image — kompletní sada sériových nástrojů
$ cargo espflash board-info
Začněte s cargo-espflash: zapadá do stejného mentálního modelu jako cargo build a board-info je první příkaz, který spusťte, pokud si nejste jistí, jakou desku držíte v ruce. Obě možnosti jsou legitimní — pokud už máte na počítači IDF, esptool je po ruce a není důvod jej měnit.
Krok 3 · Projekt

esp-generate vytvoří kostru projektu

Terminálový průvodce se zeptá na pár otázek a vytvoří reálný, kompatibilní projekt. 

$ cargo install esp-generate --locked
$ esp-generate

Sync nebo async

Běžný blokující kód, nebo embassy async — volba je na vás.

Cílový čip

Libovolný podporovaný ESP SoC vybraný ze seznamu.

Inicializace Wi-Fi

Volitelné zprovoznění rádia, připravené od začátku.

Upřesněme si to: stále provádíte cross-kompilaci a nastavení projektu tak, aby Cargo přesně vědělo, co má dělat, může být nepříjemné. esp-generate to vyřeší za vás. Jeden příkaz a máte kompilovatelný, flashovatelný projekt se správným target triple a už zapojeným HALem. Sync nebo async je volba v menu a inicializace Wi-Fi je zaškrtávací políčko. Pokud chcete skriptování, existuje headless režim s přepínači -o — takže i vy, AI agenti, se rychle naučíte, jak jej používat.
Krok 4 · Nasaďte jej

Sestavit, flashnout, hotovo

$ cargo build --release
$ cargo espflash flash --release
$ cargo espflash monitor

Stejná slovesa, která už používáte pro každý jiný Rust projekt — jen míří na mikrokontrolér namísto serveru.

Tím se kruh uzavírá. Cargo build, flash, monitor. Žádný Makefile, žádné CMake, žádný samostatný flashovací skript, žádný druhý toolchain, který se musíte naučit. Pokud jste už někdy psali v Rustu, už víte, jak toto všechno dělat — a přesně o to jde.
